# Устройства, которые запустили приложение, но не отправили запрос в Trisigma

Выборка по логам Ingress (`mpback-k8s-ingress`): устройства с версией приложения **строго выше 11.10.0**, у которых после запуска нет ни одного запроса в Trisigma Composition. Те, у кого запрос всё-таки нашёлся (позже или только в `mpback-k8s-trisigma-composition`), из выборки убираются и попадают в отдельный файл с указанием, где и когда запрос найден.

Два способа, логика одна:

| | что это | когда брать |
|---|---|---|
| `devtools.txt` | блоки для Kibana Dev Tools, ставить ничего не нужно | быстро посмотреть и выгрузить небольшой список |
| `find_no_trisigma.py` | скрипт (Python 3.8+, только стандартная библиотека): запрос + проверка кандидатов + CSV | большие окна, проверка старой выгрузки, пересечение с событиями |

> **Важно.** К вашему Kibana у меня доступа не было. Названия полей (`device_id`, `user_id`, `platform`, `app_version`, `path`) — предположение по ТЗ и старой выгрузке. Подтвердите их шагами 1–2 в `devtools.txt` или командой `discover`; если название другое, поправьте его (`--set device=…` или в запросе).

## Что считается запуском, запросом и «ошибкой»

- **Единица — устройство.** По ТЗ `visitorId` в Trisigma = `user-agent.id` = `device_uuid`, а `userId` необязателен и неавторизованным не отправляется. Поэтому «нет запроса» считается по `device_id`; `user_id` в выгрузке только для справки. Иначе пользователь, зашедший ещё с другого устройства, ложно выпадал бы из выборки.
- **Запуск** = устройство (ios/android) обратилось не менее чем в 7 разных сервисов (`/gateway/<сервис>/…`) за одну минуту, как веер запросов при старте (в старой выгрузке 7–9). Колонка `gap_before_min` показывает, сколько устройство молчало перед запуском (как в старой выгрузке); `--set min_gap_min=60` оставит только «холодные» старты.
- **Запрос в trisigma** = любой запрос, в пути которого есть `trisigma`: `/trisigma/features` (запуск, авторизация, выход) и `/trisigma/experiments`. **С любым HTTP-статусом**: упавший запрос всё равно значит, что приложение его отправило.
- **Нет запроса после запуска.** Шаг 1 (запрос ES|QL): ни одного запроса от устройства с (минута первого запуска − 2 мин) до конца окна + 30 мин. Шаг 2 (проверка кандидатов): то же **без верхней границы по времени**, в Ingress и в индексе trisigma-composition. Нашёлся — устройство исключено.
- **Версия.** `11.10.1_380` (iOS) и `11.10.1.g_20300` (Android) → `11.10.1`, как в правилах ТЗ (APPSUP-1441). Порог **строгий**: > 11.10.0. Если нужно «11.10.0 и выше» — `--set inclusive=true` (в Dev Tools замените `> 11010000` на `>= 11010000`). В старой выгрузке 32 строки на 11.9.0 и 13 ровно на 11.10.0, выше нет ни одной.
- Платформа и версия проверяются только для стороны «запуск». У самих запросов в trisigma этих полей в логе может не быть, и они всё равно учитываются.

### Почему в старой выгрузке могли быть «ошибочные» (гипотезы)

1. запрос в trisigma пришёл позже окна проверки;
2. сопоставление по `user_id`: `GET /features` уходит при запуске, авторизации и выходе, и в логе он может быть без `user_id` или с другим;
3. запрос виден только в индексе composition или путь немного отличается от ожидаемого;
4. упавшие запросы (5xx/499) посчитаны как «запроса нет».

`audit` показывает по каждой строке старого CSV, был ли запрос, где именно и через сколько минут после запуска. По этому распределению видно, какая гипотеза верна.

## Запуск

### A. Kibana Dev Tools

Откройте `devtools.txt` и вставляйте блоки по одному (Ctrl+Enter):

0. версия кластера (ES|QL нужен 8.14+);
1–2. как устроены логи и какие есть поля: подтвердите или поправьте имена полей;
3. проверка фильтров на окне в 1–2 часа: должны найтись сервисы, пути trisigma и версии. Если путей trisigma нет, основной запрос выдаст всех, и запускать его нельзя;
4. **основной запрос**: кандидаты. Начните с окна в несколько часов;
5. проверка кандидатов на запросы позже и в индексе composition (подставьте `device_id` из шага 4);
6. по желанию: пересечение с событиями без эксперимента.

### B. Скрипт

```bash
export KIBANA_URL=https://kibana.example.com   # или ES_URL=https://elastic:9200
export ES_API_KEY=...                          # или ES_USER / ES_PASSWORD, или -H "Cookie: …" (если SSO)

python3 find_no_trisigma.py discover                                  # версия ES, примеры документов, поля
python3 find_no_trisigma.py sanity --from now-2h --to now             # фильтры находят сервисы, пути trisigma, версии
python3 find_no_trisigma.py run --from 2026-09-29T00:00:00Z --to 2026-09-29T06:00:00Z --out result
python3 find_no_trisigma.py audit старая_выгрузка.csv --out old       # где старая выгрузка ошибалась
python3 find_no_trisigma.py esql --from … --to … --devtools           # тот же запрос текстом для Dev Tools
```

Окно `--from/--to` (UTC, МСК = UTC+3) — это окна **запусков**. Для больших окон добавьте `--slice-hours 3`. Перед `run` скрипт сам проверяет, что запросы к trisigma в Ingress находятся и привязаны к устройствам, иначе останавливается: с неверным фильтром в выборку попали бы все.

Настройки меняются ключом `--set имя=значение` (или словарём `CFG` в начале файла):

| ключ | по умолчанию | что это |
|---|---|---|
| `device`, `user`, `platform`, `version`, `path`, `ts` | `device_id`, `user_id`, `platform`, `app_version`, `path`, `@timestamp` | поля Ingress (`user=` пусто, если `user_id` не нужен) |
| `device_term` | пусто | keyword-вариант поля устройства, если основное `text` (например `device_id.keyword`) |
| `svc_dissect` | `/gateway/%{svc}/%{?rest}` | как из пути получить имя сервиса |
| `tri_like` | `*trisigma*` | признак запроса в trisigma в пути (регистр не важен) |
| `comp_device` | пусто | поле с `visitorId` в composition; пусто = искать id фразой по всем полям |
| `fanout_min` | `7` | сколько разных сервисов за минуту считать запуском |
| `min_gap_min` | `0` | >0: только запуски с паузой перед ними не меньше N минут |
| `min_version`, `inclusive` | `11.10.0`, `false` | порог версии и строгость сравнения |
| `buffer_min`, `pre_margin_min` | `30`, `2` | сколько минут после окна и до запуска учитывать запросы в trisigma |
| `events_index`, `ev_key`, `ev_key_source`, `ev_experiment` | пусто, `device_id`, `device`, `experiment` | пересечение с событиями (см. ниже) |

Файлы результата (`;`-разделитель, как в старой выгрузке):

- `result_final.csv`: итог: `user_id, device_id, platform, app_version, first_launch_utc, gap_before_min, launch_bursts, max_fanout_services, last_seen_utc`;
- `result_excluded.csv`: исключённые: причина, где (`ingress` / `composition`), когда и по какому пути найден запрос;
- `result_level1_all.csv`: кандидаты до проверки;
- `result_intersection.csv`: только при `events_index`, см. ниже.

`first_launch_utc` — начало минуты, в которую был веер запросов.

### Пересечение с событиями без эксперимента

`--set events_index='<индекс событий>*' --set ev_key=<поле устройства или пользователя> --set ev_experiment=<поле эксперимента>` (для ключа `user_id`: `--set ev_key_source=user`). Устройство попадает в пересечение, если в окне у него есть события и ни в одном из них эксперимента нет: поля нет, оно `null`, `""` или `[]`. Колонки `events_total`, `events_with_experiment`, `intersection` (`yes` / `no` / `unknown` — событий нет вообще).

## Ограничения и что проверено

- Проверено на **локальном Elasticsearch 8.14.3, 8.19.22 и 9.1.10 с синтетическими логами** (`tests/run_local.sh`, сценарии: нормальный запуск, запрос позже, запрос только в composition, упавший запрос, запрос без платформы/версии, разный регистр id и др.). На ваших данных не запускалось.
- Режим `--kibana-url` проверен только на эмуляторе прокси Dev Tools. Если Kibana за SSO, нужен `-H "Cookie: …"` или API-ключ.
- ES|QL появился в 8.11 и стабилен с 8.14. На более старом кластере шаг 1 не заработает (скрипт скажет об этом), `audit` и шаг 5 используют обычный DSL. На 7.x не проверялось.
- Основной запрос группирует по устройству и минуте: на суточном окне он тяжёлый для кластера, начинайте с 2–6 часов.
- Запуск считается по минутным корзинам: веер, разорванный границей минуты, не засчитается.
- Шаг 1 берёт лимит 10 000 строк; при упоре скрипт предупреждает, тогда уменьшите окно (`--slice-hours`).
